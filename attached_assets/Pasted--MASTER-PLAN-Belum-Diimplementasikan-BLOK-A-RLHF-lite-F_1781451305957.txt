BLOK H — Model Distillation (Guru Mengajar Murid)
Apa yang dibangun:

Pipeline otomatis dimana model besar mengajarkan model kecil:

Flow:

Agent Researcher identify topik yang model lokal (tinyllama/qwen2.5-small) lemah
Gunakan Groq (llama-3.3-70b atau OpenAI OSS 120B) untuk generate 500-1000 Q&A pairs berkualitas tinggi tentang topik tersebut
Format: {input: "pertanyaan", output: "jawaban berkualitas dari model besar"}
Dataset langsung masuk ke training pipeline model lokal
Kualitas training data jauh lebih tinggi dari Wikipedia random
Kenapa ini penting:

Training dari data internet = 30-40% noise
Training dari model besar yang di-curate = hampir 0% noise
Model kecil bisa "mencuri" kemampuan model besar dengan efisien
BLOK I — Multi-Agent Debate untuk Verifikasi Data
Apa yang dibangun:

Sebelum training sample masuk ke dataset, harus lulus verifikasi 3-agent:

Agent A (Researcher): Generate jawaban untuk pertanyaan X
Agent B (Code Reviewer): Kritik jawaban Agent A — apakah benar?
Agent C (Analyst): Arbitrasi — siapa yang benar?
Acceptance rule:

Consensus (A & B setuju, atau C pilih A) → masuk training
No consensus → buang sample tersebut
Track reject rate per topik → topik dengan reject rate tinggi = area yang perlu lebih banyak research
Efek:

Training dataset 3-5× lebih kecil tapi kualitas jauh lebih tinggi
Menghilangkan contoh yang ambigu atau salah sebelum meracuni model
BLOK J — Active Learning (Train yang Tidak Diketahui)
Apa yang dibangun:

Sistem yang identify area model paling tidak yakin:

Cara mengukur uncertainty:

Test model dengan 500 prompt standar di berbagai topik
Ukur: waktu respons (lama = tidak yakin), panjang jawaban, konsistensi (tanya 3x, bandingkan)
Buat uncertainty map per topik
Pipeline:

Agent Analyst jalankan uncertainty test setiap 24 jam
Top 10 area dengan uncertainty tertinggi → laporan ke Agent Researcher
Researcher cari data spesifik untuk area-area ini
Trainer prioritaskan area ini dalam training run berikutnya
Hasil: training 3-5× lebih efisien karena tidak buang siklus di topik yang sudah dikuasai
BLOK K — Automated Red-Teaming
Apa yang dibangun:

Agent khusus yang tugasnya "menyerang" model sendiri:

Jenis serangan:

Pertanyaan jebakan (pertanyaan yang tampak mudah tapi model sering salah)
Ambiguitas bahasa (pertanyaan yang bisa diinterpretasi dua cara)
Edge cases (angka ekstrem, string kosong, bahasa campuran)
Adversarial prompts (coba buat model keluar karakter/hallucinate)
Out-of-distribution (topik yang tidak ada di training data)
Flow:

Red-Team Agent generate 100 adversarial prompts per hari
Test ke model yang sedang aktif
Catat semua kegagalan: jenis kegagalan, severity
Kegagalan → masuk training set sebagai negative examples dengan correct answers
Laporan mingguan: "Model rentan terhadap X jenis serangan"

Apa yang dibangun:

Sistem untuk menambah kemampuan ke model tanpa full retraining:

Konsep:

Ketika adapter cukup matang (score stabil) → merge ke model baru = version upgrade

BLOK N — Catastrophic Forgetting Prevention
Apa yang dibangun:

Sistem yang memastikan model tidak lupa apa yang sudah bisa sebelumnya:

Golden Test Set:

200 pertanyaan fundamental yang model HARUS bisa jawab (math dasar, programming dasar, bahasa Indonesia dasar)
Tersimpan di golden_test_set table
Admin bisa tambah/edit via UI
Validation Rule (ketat):

Setiap selesai training → auto-test golden set
Skor golden set < 85%? → Training job DITOLAK otomatis
Skor turun > 5% dari sebelumnya? → Auto-rollback ke versi sebelumnya
Log semua perubahan skor untuk tracking trend
Replay Buffer:

Setiap training run selalu include 20% sample dari golden set

Dikenal sebagai teknik "Experience Replay" di RL
